# 리스닝 학습 앱 개발 설계 v2

상태: 설계 v2 / 첫 로컬 앱 구현 및 실행 완료, 전체 설계 중 일부 구현
작성일: 2026-09-19

실행 방법과 실제 구현 범위는 [앱 README](../listening-app/README.md)를 참고한다. 아래는 목표 설계를 포함하며 모든 항목이 구현된 것은 아니다.

개정: 링크 단독 입력, 자동 콘텐츠 준비, 장기 학습 추적, 학습 중 피드백, 정기 추천.

현재 구현 명세는 [학습 자동화 설계 v2](adaptive_learning_design.md)와 본 문서를 함께 따른다. 링크만 입력하며 자막·학습 구간·약점 사전 설문은 필수가 아니다. 자막 라이브러리·AI·로컬 서비스로 준비하고 학습 반응으로 추천을 갱신한다.

## 1. 목적과 제품 결정

사용자가 처음 듣는 영어 기술 설명에서 긍정·부정, 숫자·단위, 조건·결과, 관찰·추측을 이해하도록 돕는다. 연구 비교나 장시간 진단이 아닌 매일 실행할 수 있는 연습이 제품의 중심이다. 논문은 훈련 선택의 근거로만 사용한다.

첫 사용자는 한국어 설명을 선호하며, 반도체 테스트·불량 분석·제품 평가 관련 영어를 듣는다. 실제 상대는 다양한 언어 배경의 화자다. 주어진 Slow Mo Guys 영상은 기술 설명과 숫자·관찰을 연습할 주 자료로 유지한다.

첫 버전은 PC 브라우저 중심의 반응형 개인용 웹앱으로 만든다. 로그인 없이 로컬 저장으로 시작하고 휴대폰에서도 화면은 사용할 수 있게 한다. 기기 간 동기화는 후속 범위다. 앱 명칭은 잠정적으로 '리스닝 연습장'을 사용한다.

기존 논의에서의 '영상 가리고 소리만'은 확정 사양이 아니다. YouTube 내장 플레이어는 보이는 상태를 기본으로 하고 정책·재생 제약을 구현 전에 확인한다. 오디오 전용 훈련에는 별도로 사용 권한이 확보된 녹음 또는 합성 음성을 사용한다.

## 2. 현재 학습 가설

| 관찰 | 우선 대응 |
|---|---|
| 글로 이해하는 표현도 연속 발화에서 놓침 | 표적 구절의 소리와 문구 연결 |
| 글을 확인하면 선명하게 들리는 사례가 있음 | 영어 문구 피드백 후 자막 없는 재청취 |
| 일부 표현은 읽어도 조합 시간이 필요 | 구조와 의미 덩어리 연습 |
| 긍정·부정 소리가 혼동됨 | 짧은 발화의 의미 구분 |
| 길어지면 부정 의미를 놓침 | 조건·이유를 덧붙인 설명 이해 |

위 항목은 확정 진단이나 표준 능력 등급이 아니다. 사용자를 하나의 약점 유형으로 고정하지 않는다. 이전 대화 답변은 '대화에서 확인한 기록'으로만 이관하며 정확한 반복 횟수나 정량 점수는 추정해서 채우지 않는다.

## 3. 첫 버전의 학습 콘텐츠

### 핵심 A: 긍정·부정과 확실성

단순 not 탐지 대신 발화의 의미를 구분한다. 내용에 따라 선택지는 '통과 / 미통과 / 아직 판단 불가', '확인됨 / 확인 안 됨 / 가능성만 제시'처럼 달라진다. '모르겠어요'는 항상 별도 선택지다.

초기 순서는 운영 가설이며 사용자 반응에 맞춰 바꾼다.

1. 짧은 긍정·부정: passed / didn't pass.
2. 부정 의미 유지: didn't fail → didn't fail during the test → didn't fail … but leakage increased.
3. 완료·확실성: haven't confirmed yet / confirmed / may be caused by.
4. 범위: not all / none / only some.

각 단계는 몇 문항의 진전만으로 자동 완료 처리하지 않는다. 특히 'not all'은 '전부 아님'을 뜻할 뿐 '일부는 반드시 그렇다'고 정답을 과도하게 좁히지 않는다. 'didn't expect X'에서 X의 실제 발생 여부를 문맥 없이 확정하지 않는다. didn't fail을 모든 평가 항목에 합격했다는 의미로 확대하지 않는다.

can/can't에는 단일 발음 법칙을 강요하지 않는다. 화자와 문맥이 포함된 실제 발화를 검증해 제공한다. 합성 음성이 not만 부자연스럽게 강조한 자료는 자연 발화 연습으로 간주하지 않는다.

### 핵심 B: 같은 구조의 다른 문장

공통 어순뿐 아니라 의미 관계를 기준으로 묶는다. 최초 후보는 수단·목적, 예상과 실제, 조건·변화, 최대한의 정도 표현이다.

- We used X to Y: 수단 / 목적.
- We didn't expect X to Y: 예상하지 못한 사건.
- X increases when Y: 변화 / 조건.
- as … as possible: 최대한의 정도.

패턴 하나에 4~6개 사례를 초기값으로 잡는다. 쉬운 어휘의 짧은 문장으로 시작해 대상·동사·수치를 바꾸고, 익숙해지면 다른 구조를 섞는다. 낯선 단어·억양·길이를 동시에 늘리지 않는다. 품사 배열만 같거나 주제만 같은 문장은 자동으로 같은 패턴으로 승인하지 않는다.

### 핵심 C: 영상에서 설명 따라가기

숫자+단위+대상, 실험 조건, 관찰, 화자의 판단을 짧은 구간에서 확인한다. 영상의 원래 문맥으로 돌아가는 활동을 매 세션에 포함하는 것을 목표로 한다. 소재가 부족하면 확보된 콘텐츠 범위를 명시하고 억지로 패턴을 배정하지 않는다.

## 4. 사용자 화면과 행동

### 홈: 오늘의 연습

- 주요 버튼: '오늘 연습 시작'. 초기 권장 분량은 약 10분이며 연구로 정해진 최적 시간이 아니다.
- 보조 버튼: '이어서 하기', '연습 주제 고르기', '학습 기록', '내 영상'.
- 설명 예: '오늘은 실패 여부를 놓치지 않는 연습을 합니다.'
- 연구명, 효과크기, 내부 약점 분류 코드는 사용자 첫 화면에 표시하지 않는다.

### 연습 화면

```text
오늘의 연습                                  2 / 5
이 설명을 듣고 결과를 골라보세요.

[영상 또는 음성 플레이어]
[듣기] [다시 듣기]

[실패하지 않음] [실패함] [발생 여부는 말하지 않음]
[모르겠어요]

필요할 때: [영어 문장 보기] [속도 조절]
```

선택지 수와 문구는 문항별로 정한다. 재생 전에는 답변을 비활성화하지만 네트워크 오류가 난 경우 이를 오답으로 저장하지 않는다. 선택지는 필요 시 청취 후 공개하여 읽기 부담을 줄인다. 정답을 암시하는 문항 제목·영상 설명을 별도로 점검한다.

### 도움과 피드백

응답 직후 핵심 뜻을 짧게 보여준다. 틀렸거나 모를 때만 표적 구절과 문구를 제시한다. 예: '실패하지 않았다는 설명입니다. didn’t fail 부분을 다시 들어보세요.'

- '그 부분 듣기': 검증된 구절 경계로 재생.
- '뜻 확인': 한국어 의미와 필요한 표현 설명.
- '문장 전체 듣기': 자막을 접고 원래 속도·문맥으로 복귀.
- '다른 문장 듣기': 같은 구조의 다른 내용으로 이동.

자막 또는 해설을 본 후의 정답은 '도움 받고 이해'로 기록한다. 이미 본 정답을 맞히는 활동을 새 문장의 성공으로 표시하지 않는다. 반복이 길어지면 다음 활동을 제안하되 학습자의 재생을 강제로 막지 않는다.

### 세션 종료와 기록

간단한 요약만 제공한다. 예: '새 문장 3개 중 2개는 도움 없이 이해했어요. 다음에는 조건이 붙은 문장으로 이어갑니다.'

- 도움 없이 이해한 새 문장 수 / 시도한 새 문장 수.
- 연습으로 익힌 표현 1~3개.
- 다음 연습 제안 하나.

'영어 듣기 20% 향상' 같은 근거 없는 종합 수치를 만들지 않는다. 기록 화면에서만 이전 구절과 새 구절 결과를 나누어 확인할 수 있게 한다. 매일 긴 설문이나 의무 진단은 없다.

## 5. 한 세션 구성과 적응 규칙

일반 세션은 짧은 복습 1개, 오늘의 표적 연습 2~3개, 새 사례 또는 영상 복귀 1개로 시작한다. 시간과 문항 수는 부담에 따라 줄일 수 있다.

초기 추천은 학습자의 최근 몇 번 반응에 대한 단순 규칙으로 구현한다.

- 소리도 뜻도 어려움: 짧은 문장으로 돌아가 문구·의미를 확인.
- 문구를 보면 이해함: 동일 구조의 다른 문장으로 소리 식별 연습.
- 짧게는 되지만 길게는 놓침: 익숙한 골격에 조건 한 개만 추가.
- 새 사례도 이해함: 다른 구조와 섞거나 다른 화자로 확장.
- 한 번 틀림: 즉시 능력 수준을 낮추지 않고 피드백과 다른 사례 제공.

첫 응답, 자막·해설을 본 응답, 반복 후 응답을 내부적으로 구분하지만 사용자에게 연구 실험 절차처럼 제시하지 않는다. 피드백 전 선택을 수정할 수 있으며 이후에는 최초 응답을 보존하고 별도 시도로 저장한다.

## 6. 콘텐츠 확보·검수

현재 자산은 YouTube 링크와 자동 전사·번역이 담긴 XLSX다. 오류가 있으므로 이를 그대로 확정 정답으로 사용하지 않는다.

콘텐츠 준비 순서:

1. XLSX를 읽어 시간·영문·번역 후보를 구조화한다. 원본은 보존한다.
2. 새 영상은 링크로 자막을 자동 수집하고 AI가 구간·문항 후보를 준비한다. 실제 음성 대조 가능 여부와 원문·문맥 근거를 검사하고 검증 상태를 구분한다.
3. 검증된 구간만 채점형 문항으로 승인한다. 미검증 구간은 자유 청취로 제한한다.
4. 영상에서 충분히 확보하지 못하는 긍정·부정 대비나 패턴 변형은 별도 녹음 또는 합성 음성으로 보충한다. 출처와 음성 종류를 표시한다.
5. 합성 문장은 문법·자연스러움·의미와 음성을 검수한다. 실제 발화로 연결하는 사례를 확보한다.

출시용 초기 목표는 검증된 영상 구간 6~8개와 짧은 보조 발화 12~18개다. 목표 개수이며 현재 확보 완료를 뜻하지 않는다. can/can't, 부정 범위, 음질이 불명확한 문항은 무리하게 출시하지 않는다.

## 7. 구현 구조 제안

개인용 로컬 웹앱으로 React + TypeScript + Vite 프론트엔드와 Python 로컬 서비스, SQLite 저장소를 제안한다. 정확한 버전은 구현 시 확인한다. 웹 서버를 통해 실행하고 HTML 파일 직접 열기를 전제로 하지 않는다.

- 화면: Home, Practice, SessionSummary, History, Library(영상 추가·선택·학습팩 가져오기), Settings.
- 학습 로직: 문항 순서, 도움 단계, 다음 연습 추천을 UI와 분리.
- 플레이어 계층: YouTube 영상과 로컬 오디오를 같은 인터페이스로 제어.
- 콘텐츠: 자막 자동 수집과 AI 문항 준비를 로컬 서비스에서 실행. 자동 생성에는 설정된 AI 공급자가 필요하며 장애 시 기존 콘텐츠로 계속 연습.
- 저장: SQLite가 기준 저장소, 브라우저는 임시 상태·미전송 사건을 보관. 콘텐츠 버전·복습·기준선을 포함해 백업/복원을 제공.
- 첫 버전 채점: 검수된 선택형 문항 중심. 자유 답변은 노트로 저장하고 자동 정답 판정하지 않음.
- 온라인 조건: YouTube 구간은 인터넷 필요. 저장 기록 및 로컬 음성의 오프라인 제공은 별도 구현 범위.

YouTube 구간 제어, 임베드 허용 여부, 사용 가능한 속도, 자막 제어, 플레이어 크기·표시 정책은 구현 전 공식 문서와 실제 영상에서 검증한다. 정밀한 구절 반복은 별도 오디오가 더 적절할 수 있다. 영상 다운로드나 오디오 추출은 기본 경로로 삼지 않는다.

## 8. 핵심 데이터

| 데이터 | 필수 항목 |
|---|---|
| Source | id, 종류(youtube/audio), URL/파일, 화자, 음성 종류, 출처/사용 조건 |
| Clip | id, sourceId, 시작·끝, transcript, 의미, 검수 상태, 문맥 설명 |
| Exercise | id, clipId, 학습 목표, patternId, 선택지와 정답, 설명, 표적 구간, 다음 사례 ID |
| Attempt | exerciseId, 내용 버전, 최초 응답, 최종 응답, 재생·속도·도움 이벤트, 최초 노출 여부, 시각 |
| Session | id, 문항 목록, 현재 단계, 시작·종료 시각 |
| LearnerSkill | 사용자 ID, 영상 독립적인 학습 목표 ID, 최근 근거 시도 ID, 추천 지원 단계 |
| ReviewItem | 사용자 ID, clipId/exerciseId, patternId, 복습 예정일, 보류·재생 불가 상태 |
| ContentPack | id, version, sourceIds, clips, exercises, assets, 검수 상태 |
| BaselineSnapshot | id, 작성일, 실제 점검일, 정성/정량 구분, 근거, 문항 버전, 조건 |

원래 발화 단위의 clipId로 노출을 추적한다. 같은 구간을 다른 문제로 바꿔도 '처음 듣는 발화'로 세지 않는다. 긍정·부정이 바뀐 별도 음성은 서로 다른 구간이지만 같은 패턴 가족임을 기록한다. 단순히 패턴이 같다는 이유로 새 발화 자격을 없애지는 않는다.

브라우저 임시 기록은 서비스로 동기화하며 로컬 데이터베이스와 자산의 백업을 제공한다. API 키나 계정 비밀값은 프론트엔드 콘텐츠에 넣지 않는다.

## 9. 동작 상태와 예외

문항 상태: 준비 → 재생 → 응답 → 피드백 → 도움 연습(선택) → 다음 문항. 세션 새로고침 후에는 저장된 문항의 일시정지 상태로 복원하고 자동으로 소리를 재생하지 않는다.

- 플레이어 로딩 실패: 재시도 / 원본 열기 / 문항 건너뛰기. 실패를 오답으로 처리하지 않음.
- 임베드 제한: 원본에서 수동 청취 가능하나 재생 횟수·속도는 미확인으로 기록. 제어 가능했다고 표시하지 않음.
- 일시정지·버퍼링: 벽시계 타이머가 아닌 플레이어의 현재 재생 위치로 종료를 판단.
- 화면 이동: 기존 재생 중지. 이전 문항의 타이머·이벤트가 다음 문항을 중단하지 않도록 정리.
- 저장 실패: '저장되지 않았습니다' 표시 및 재시도/내보내기. 저장 성공으로 표시하지 않음.
- 가져오기: 스키마와 버전을 검사하고 기존 기록을 말없이 덮어쓰지 않음.

## 10. 디자인 원칙

한국어 안내, 큰 재생 버튼, 읽기 쉬운 글자, 차분한 화면을 사용한다. 한 화면에 한 학습 행동만 강조한다. 자막·해설은 접어두고 필요할 때 연다. 정오답을 색상만으로 전달하지 않으며 키보드 탐색과 명확한 포커스를 지원한다. 영상 주변을 다른 요소로 가리지 않는다.

과도한 배지, 경쟁 순위, 연속 학습 압박은 첫 버전에 넣지 않는다. 도중에 끝내도 진행 상태를 저장한다.

## 11. 개발 순서와 완료 조건

### 1단계: 재생과 콘텐츠 검증

YouTube 임베드와 구간 재생을 실제 영상으로 확인하고, 검증된 콘텐츠 소량을 준비한다. 오디오 자산 확보 방식도 결정한다. 실패하면 검증 가능한 소스 경로를 먼저 해결한다.

### 2단계: 학습 흐름 구현

홈 → 듣기 → 의미 선택 → 구절 도움 → 다른 사례 → 종료 화면을 연결한다. 긍정·부정과 구조별 연습 각 한 묶음으로 먼저 끝까지 작동시킨다.

### 3단계: 기록과 연습 추천

로컬 저장, 이어하기, 내보내기/가져오기, 소수의 추천 규칙을 구현한다. 기존 대화 기록은 정성 메모로 연결한다.

### 4단계: 사용자와 실제 연습

짧은 세션을 진행하고 듣기·피드백에 방해되는 조작을 줄인다. 새 문장 몇 개의 반응을 다음 연습 선택에 사용한다. 콘텐츠를 확장한다.

완료 검증은 학습 경험에 중요한 동작에 집중한다: 구간 시작·종료, 중복 재생 방지, 정답 피드백, 도움 노출 기록, 최초 응답 보존, 새 발화 판별, 새로고침 복원, 데이터 내보내기·가져오기, 오류 시 오답 미기록. 데스크톱과 좁은 화면에서 재생 버튼·선택지·자막이 겹치지 않는지 확인한다.

## 12. 첫 버전에서 미루는 기능

회원가입, 클라우드 동기화, 음성 녹음·발음 점수, LLM 자유답변 자동 확정 채점, 사용자 연구 대시보드, 종합 영어 등급 추정은 제외한다. 링크 기반 자동 문항 준비는 첫 버전에 포함하되 모든 영상의 성공은 보장하지 않는다. 품질 검사에서 보류된 자료는 다른 연습으로 대체한다.

## 13. 영상 변경과 연속 학습 — 첫 버전 필수

영상 교체는 원본 Source 덮어쓰기가 아니라 Library에 새 Source/ContentPack을 추가하고 활성 영상을 선택하는 방식이다. 사용자는 링크만 입력한다. XLSX/SRT/VTT 가져오기는 고급 보조 경로로 남긴다. 일반 흐름은 [영상 변경 가이드](video_change_guide.md)를 따른다.

준비 상태는 '영상 확인 → 자막 정리 → 연습 준비 → 전체/일부 학습 가능'이며 실패·보류 사유를 구분한다. 자동 처리하고 불확실한 구간만 추가 검수 대상으로 보류한다. 사용자가 학습팩을 직접 만들어 가져올 필요는 없다. 자료 준비 중에는 기존 세션·복습을 계속 사용할 수 있다.

학습 목표와 복습 큐는 영상과 독립적으로 보존한다. 활성 영상 변경은 이후 신규 연습 선택에만 적용하고 진행 중인 세션의 문항 목록은 고정한다. 새 영상에 원하는 패턴이 없으면 기존 영상·보조 음성으로 연결하며 자료 부족을 실패로 처리하지 않는다. 사용자 선택에 따라 기존 복습을 보류할 수 있다.

동일 YouTube ID 재등록은 기존 자료와 연결한다. URL의 공유·시작 시각 파라미터 차이로 새로운 영상이라고 처리하지 않는다. 겹치는 시간 구간과 자막 개정은 기존 노출 이력을 참조해 새 발화 여부를 판단한다. 다른 영상에 재사용된 동일 발화를 자동 탐지할 수 없다면 사용자 노출 신고와 검수 메타데이터를 반영하고, 미확인을 미노출로 확정하지 않는다.

학습팩 업데이트는 버전별로 저장하고 완료된 시도는 당시 문항·정답 버전에 연결한다. 정답 수정 시 과거 성과를 조용히 바꾸지 않고 정정 이력을 표시한다. 가져오기는 전체 검증 후 한 번에 반영하며 실패하면 기존 팩·기록을 유지한다. 보관 처리는 기록 삭제와 분리한다.

로컬 배포는 앱 주소와 포트를 고정하고 로컬 서비스 DB에 기록을 모은다. 백업은 시도뿐 아니라 콘텐츠 버전·학습 상태·복습 큐·기준선도 포함한다. 누락 오디오 파일은 재연결하고 영상 자체는 저장하지 않는다. 기기 간 자동 동기화는 제공하지 않는다.

추가 완료 조건: 영상 A에서 연습 후 B를 추가해도 A의 기록과 복습이 유지됨; B 준비 중 A 사용 가능; 동일 영상 재등록 시 이력 분리 안 됨; 새 영상 선택 후 중단 세션 복원 가능; 잘못된 팩 가져오기 시 기존 데이터 보존; 백업 복원 후 복습·콘텐츠 연결 유지; 영상 재생 불가 시 같은 목표의 대체 연습으로 이동 가능.

## 14. 최초 수준과 한 달 점검

[2026-09-19 최초 수준 기록](listening_baseline_2026-09-19.md)을 정성 기준선으로 보존한다. 한 달 비교 예정일은 2026-10-19이며 실제 시행일도 별도 저장한다. 긍정·부정에 대한 현재 근거는 자기보고이므로 객관적 점수를 소급 생성하지 않는다.

앱 준비 후 짧은 최초 점검을 실제 시행일에 기록하고, 한 달 뒤 비슷한 난도의 새로운 발화로 다시 확인한다. 기존 구간의 기억 유지와 새로운 구간의 이해를 분리하되 사용자에게 긴 실험 절차를 요구하지 않는다. 영상 변경 시 자료 난도·화자·주제 차이와 학습량을 함께 보며 다음 연습을 조정한다. 월간 점검은 미루거나 건너뛸 수 있고 연습을 차단하지 않는다.
