# 리스닝 학습 자동화 설계 v2

작성일: 2026-09-19 / 상태: 첫 로컬 앱에 일부 구현

현재 구현 범위와 검증 결과는 [앱 README](../listening-app/README.md)를 참고한다. 아래 자동화 요구사항 전체의 구현 완료를 의미하지 않는다.

## 제품 원칙

사용자는 YouTube 링크만 입력한다. 자막 파일, 학습 구간, 약점 목록, 이전 학습 구간을 등록의 필수 입력으로 요구하지 않는다. 앱은 자료를 준비하고 학습 중 발생하는 응답·도움 사용에서 다음 연습을 정한다. 장기간의 목표는 새로운 발화를 이해하는 능력이며 진단은 연습에 필요한 만큼만 한다.

본 문서는 app_design.md v1.1의 수동 학습팩 중심 흐름과 정적 프론트엔드 중심 구현을 대체한다. 최초 수준 기록은 그대로 보존한다.

## 1. 링크 하나에서 시작하는 흐름

1. 링크 정규화 및 영상 ID 중복 확인.
2. 재생 가능성·영어 자막 확보를 병렬 준비하고 작업 상태를 저장.
3. 이용 가능한 영어 원문 자막을 수집하고 원본·시간·출처를 보존.
4. 문장 경계와 앞뒤 문맥을 연결해 학습 후보 구간 생성.
5. AI가 의미·구조·숫자·부정·조건·관찰/추측 후보를 분류하고 문항 초안 생성.
6. 자동 품질 규칙과 근거 검사로 학습 가능한 문항을 승인하거나 보류.
7. 기존 학습 이력과 연결해 첫 세션 제안. 완성된 일부 구간부터 사용하고 나머지는 후속 준비.

UI는 '영상 확인 중 → 자막 정리 중 → 연습 준비 중 → 시작하기'로 단순화한다. 백그라운드 준비가 길어지거나 실패해도 기존 연습을 사용할 수 있다. 링크를 넣었다고 기존 진행 중 세션이 교체되지 않는다.

## 2. 자막 수집의 실제 범위

2026-09-19 공개 문서 확인:

- [youtube-transcript-api](https://github.com/jdepoix/youtube-transcript-api): 생성 자막과 수동 자막을 가져오고 text/start/duration을 제공한다. 클라우드 IP 또는 과도한 요청 차단 가능성이 문서화돼 있다. 기본 자막 수집 어댑터 후보다.
- [yt-dlp](https://github.com/yt-dlp/yt-dlp): 수동·자동 자막 옵션을 제공한다. 자막 수집 대체 어댑터 후보이지 별도의 고품질 전사 엔진이 아니다.
- [YouTube captions.download](https://developers.google.com/youtube/v3/docs/captions/download): 영상 편집 권한을 요구하므로 임의의 공개 영상 자막을 공식 API 하나로 모두 얻는 설계는 불가하다.

라이브러리는 존재하는 자막을 수집한다. 자동 전사의 오인식이나 단어 수준 시간 정밀도를 자동 보증하지 않는다. 수동 영어 원문을 우선 후보로 삼되 정확하다고 무조건 확정하지 않는다. 번역된 영어 자막은 영어 발화의 원문으로 사용하지 않는다.

자막이 없으면 사용 권한과 기술적 접근이 확보된 음원에 한해 별도 ASR와 정렬을 고려한다. 링크만으로 항상 음원을 취득하거나 전사할 수 있다고 약속하지 않는다. 접근 차단을 반복 우회하는 방식은 기본 경로에 넣지 않는다. 횟수를 제한한 재시도, 캐시, 실패 사유 보존을 사용한다.

실패 시에는 '이 영상은 현재 연습 준비가 어렵습니다'와 함께 준비 가능한 대체 영상 및 기존 연습을 제공한다. 자막 첨부는 고급 선택지로만 남긴다. 사용자가 파일을 준비해야만 학습이 이어지는 구조는 제거한다.

## 3. 자동 문항의 품질과 음성 근거

자막 수집 성공, 텍스트 품질 검사, 음성과의 일치 검증은 별도 상태다. AI가 문장을 자연스럽게 바꿨다고 음성이 확인된 것은 아니다. 원문은 수정하지 않고 교정 후보와 사유를 별도로 저장한다.

- 모든 정답·해설은 원문 구간과 문맥의 근거 위치를 가진다.
- 부정, 숫자, 단위는 오류 시 의미가 뒤집히므로 더 엄격히 취급한다. 불일치·문맥 충돌·음성 불확실성이 있으면 해당 문항은 채점·능력 갱신에서 제외한다.
- 음성 대조 경로가 없는 자료를 '음성 검증 완료'라고 표시하지 않는다. 해당 자료는 참고 청취로 제공하고, 검증 가능한 대체 구간에서 핵심 훈련을 진행한다.
- ASR 두 개가 일치하거나 AI 두 번이 동의해도 정답 확정의 충분조건은 아니다. 실제 음성 접근 여부, 출처와 경계 품질을 함께 기록한다.
- 부정어 유무, 수치·단위 보존, 선택지 모순, not all·didn't expect의 과잉 해석, 단절된 문맥을 규칙 검사한다.
- '답이 이상해요'를 누르면 콘텐츠 문제로 접수하고 학습자 약점으로 반영하지 않는다. 수정은 버전으로 보존한다.

검수는 불확실한 일부 자료에 집중한다. 사용자에게 검수 노동을 기본 요구하지 않고, 보류 중에는 다른 준비된 자료를 선택한다.

## 4. 학습 과정에서 얻는 피드백

| 자동 관찰 | 활용 | 단정하면 안 되는 것 |
|---|---|---|
| 첫 응답과 정답의 차이 | 부정/수치/조건별 연습 후보 | 오답 한 번으로 원인 확정 |
| 다시 듣기·구간 되감기 | 어려운 구절 후보, 다음 지원 선택 | 반복 = 반드시 이해 실패 |
| 영어 자막 후 개선 | 소리 식별 지원 후보 | 반복·읽기 효과를 완전히 분리했다고 주장 |
| 뜻 설명 후 개선 | 표현 의미 학습 후보 | 자막만 본 경우와 같은 증거로 합산 |
| 속도 변경 | 속도 지원 선호 및 효과 | 느리게 듣기를 낮은 능력으로 고정 |
| 긴 문장에서만 실패 | 정보 유지 연습 후보 | 문장 길이가 유일한 원인 |
| 건너뛰기·화면 이탈 | 세션 부담 조절 | 건너뛰기를 오답 처리 |
| 다른 문장·화자에서 성공 | 지원을 줄일 근거 | 같은 문장의 재정답을 일반화로 계산 |

세션당 능동 질문은 기본 0~1회, 답변은 한 번 누르기로 끝낸다. 원인이 계속 불분명해 다음 연습 선택에 도움이 될 때만 '소리가 안 잡힘 / 뜻이 낯섦 / 집중을 놓침' 등을 묻고 건너뛰기를 허용한다. 이는 최초 운영값이며 과학적으로 정해진 질문 빈도가 아니다.

외부에서 이미 본 영상은 자동으로 알 수 없다. 앱 안의 노출은 자동 기록하고, 외부 시청은 기본 '미확인'이다. 필요할 때 '이미 익숙한 부분이에요' 선택지를 제공한다. 주로 학습 조절에 사용하며 새 발화 성과 표시는 '앱에서 처음 연습한 구간'으로 정확히 표현한다.

## 5. 장기 학습 이력과 학습 상태

재생 시간·출석보다 첫 이해, 필요한 지원, 며칠 뒤 유지, 다른 문장에서도 이해하는지를 추적한다.

### 원시 사건 기록

사용자/세션/콘텐츠 버전/구간 ID, 사건 시각, 재생·일시정지·되감기·속도·자막·해설 노출, 응답과 수정, 자동 추천 사유를 저장한다. 중복 이벤트는 id로 제거한다. 버퍼링·백그라운드·일시정지 시간은 학습 시간과 구분하고, 탭이 열려 있다는 사실을 집중 시간으로 표시하지 않는다. 로그는 추가 방식으로 보존하고 요약은 재계산 가능하게 한다.

### 학습 상태

긍정·부정 소리 식별, 부정 범위/확실성, 숫자+단위+대상, 구조별 의미, 조건·결과, 긴 설명 연결을 분리한다. 각 영역은 다음 상태를 가진다.

- 관찰 부족 / 도움과 함께 연습 중 / 새 사례에서 일부 독립 이해 / 여러 사례에서 독립 이해 / 복습 필요.
- 근거 시도 목록, 최근 확인일, 화자·문장 수, 지원 조건, 콘텐츠 신뢰 상태를 함께 저장한다.
- 초기에는 설명 가능한 규칙을 사용한다. 여러 미학습 사례·여러 날의 반응이 쌓이기 전 '숙달'을 선언하지 않는다. 동일 문장의 반복 정답은 근거를 과도하게 늘리지 않는다.
- 오랫동안 점검하지 않으면 '최근 확인 필요'이지 자동으로 능력이 떨어졌다는 뜻은 아니다.
- 난도·화자가 바뀐 실패는 조건별로 반영하고 사용자 전체 상태를 초기화하지 않는다.

첫 버전에서 근거 없는 확률이나 정교한 지식추적 모델의 정확도를 주장하지 않는다. AI는 구조 분류·해설·다음 사례 생성과 추천 사유 작성에 사용하고, 기록 갱신·노출 판정·채점 조건은 추적 가능한 코드가 담당한다.

## 6. 다음 연습과 복습 선택

매 세션은 '확인할 복습 → 현재 목표에 맞는 새 사례 → 실제 문맥 적용'을 짧게 구성한다. 고정 비율은 사용자의 부담과 콘텐츠에 따라 조정한다.

우선 선택 기준은 복습 예정, 최근 어려움, 실제 기술 설명 관련성, 적절한 난도, 아직 안 들은 사례, 화자 다양성이다. 같은 영상·표현만 계속 추천되지 않게 제한한다. 새 자료 탐색도 소량 포함한다.

- 도움 없이 새 사례를 이해: 다음 복습 간격을 늘리거나 조건을 하나 추가.
- 도움을 받아 이해: 가까운 학습일에 다른 사례로 다시 연습.
- 반복해도 어렵거나 뜻도 모름: 더 쉬운 구문·어휘 지원으로 전환.
- 지루함/너무 어려움: 한 번 선택으로 즉시 세션 조절.

영상이 바뀌어도 학습 목표·복습 일정·출발점은 유지된다. 학습 구간은 AI가 문맥 완결성, 길이, 어휘, 말 속도 추정, 목표 구조를 바탕으로 고른다. 자막 기반 속도는 음성 측정값이 아닌 추정으로 저장한다. 선정이 불안정한 구간은 제외한다.

## 7. 정기 자료 추천

첫 버전은 주 1회 새 후보를 확인하는 주기를 기본 설계값으로 둔다. 앱 실행 시 마지막 조사일이 오래됐으면 갱신한다. 로컬 앱이 꺼져 있을 때도 실행하려면 별도 상시 서버/예약 실행 구성이 필요하므로 자동 실행을 이미 설정했다고 표시하지 않는다.

공식 기술 교육 채널, 반도체 테스트·계측·불량 분석 설명, 실험·관찰 영상과 필요한 일상 대화를 후보 범주로 둔다. 실제 사이트 목록은 구현 시 조사·검증하고, 아직 조사하지 않은 추천 링크를 생성하지 않는다.

후보 링크 존재·재생·자막 가용성을 확인하고, 학습 목표 적합성·길이·난도·음질·최근 자료 중복을 검토한다. 우선 3개 내외를 제안하며 '최근 연습한 조건 표현을 다른 화자로 들어볼 수 있어요'처럼 이유를 짧게 붙인다. 최신성 자체보다 학습 적합성이 우선이다. 사용자는 '이걸로 연습'만 누르면 된다.

추천 거절·시청 중단을 능력 부족으로 해석하지 않는다. 외부 알림·메일 전송은 기본 기능이 아니다. 조사 결과와 추천 시각을 기록하고 실패 시 이전 검증 후보로 이어간다.

## 8. 수정된 기술 구조

프론트엔드 React/TypeScript + 로컬 Python 서비스 + SQLite를 초기 개인용 배포안으로 제안한다. Python 서비스가 자막 라이브러리, 작업 큐, 콘텐츠 준비, AI 공급자 호출을 담당한다. 사용자는 설치 후 브라우저 화면만 사용한다. 정확한 의존성·음성/AI 공급자는 구현 검증에서 선택한다.

- SQLite: 사건 로그, 콘텐츠 버전, 학습 상태, 복습, 추천·작업 상태의 기준 저장소.
- 브라우저 저장: 임시 응답·미전송 사건 큐와 UI 상태. 복귀 시 id 기반 동기화.
- 단계별 작업: metadata → captions → segments → exercises → checks → ready/partial/blocked. 재시작해도 이어지고 같은 영상 작업 중복을 방지한다.
- AI 공급자 어댑터: API 키는 로컬 서비스/서버에 보관. 비용·한도·재시도 설정과 결과 캐시를 둔다. 공급자 미설정 시 기존 준비 콘텐츠는 계속 사용하고 자동 생성 불가를 명확히 표시한다.
- 최초 설치의 AI 공급자/실행 환경 설정은 일반 영상 입력과 분리한다. '링크만 입력'이 서버·API·운영 비용이 전혀 없다는 뜻은 아니다.
- 분석에 필요한 자막과 요약만 전송하고 개인 업무 내용·전체 학습 로그는 기본 전송하지 않는다. 설정에서 전송 범위와 저장·삭제·백업을 제어한다.
- 외부 자막·사이트 내용은 분석할 데이터로만 취급하고 그 안의 지시를 실행하지 않는다. URL은 허용한 YouTube 호스트/ID로 검증하고 로컬·사설 주소 요청을 차단한다.
- 백업: SQLite/구조화 내보내기, 콘텐츠 버전, 복습 상태, 기준선, 필요한 로컬 자산. 키는 백업에서 제외한다. 이전 IndexedDB 설계와 달리 서비스 DB가 기준이며 이중 기준 저장소를 만들지 않는다.

## 9. 출시 순서와 확인할 동작

1. 현재 제공 영상으로 자막 수집과 오류 분류를 실제 실행한다. 아직 실행 검증한 것으로 간주하지 않는다.
2. 링크만 넣고 검증 가능한 일부 문항까지 준비되는 전체 흐름 구현. 자막 없음·차단·AI 실패 시 대체 학습도 확인.
3. 사건 기록, 복습, 목표별 추천, 영상 전환의 연속성 구현.
4. 짧은 사용 세션에서 질문 부담을 줄이고 추천 규칙을 조정.
5. 주간 후보 갱신과 실제 추천 품질 확인.

필수 검증: 원문에 없는 부정·수치 생성 방지; 불확실한 문항이 사용자 약점으로 반영되지 않음; 반복 정답과 새 사례 구분; 외부 노출 미확인 보존; 네트워크 오류·중복 이벤트·재시작에도 기록 보존; 영상 교체 후 복습 유지; AI 공급자 장애 시 기존 학습 지속; 백업 복원 후 동일한 상태 복원.

한 달 비교는 별도 긴 검사보다 누적된 새 사례의 첫 반응과 짧은 월간 점검으로 진행한다. 자료 난도와 도움 조건을 함께 보며, 기록이 부족한 영역은 부족하다고 표시한다.
