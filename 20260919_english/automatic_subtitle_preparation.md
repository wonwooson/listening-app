# 새 영상의 자막 자동 준비

## 사용 흐름

1. ‘내 영상’에 YouTube 링크를 넣는다.
2. 앱이 youtube-transcript-api로 영어 수동 자막을 찾는다. 없으면 영어 자동 자막을 찾는다.
3. AI가 전체 자막에서 문장, 문장 안의 청크, 관련 문장을 묶는 문단을 구분한다.
4. 앱이 모든 단어의 순서와 범위가 빠짐없이 포함됐는지 검사한다.
5. 준비 완료 후 ‘듣는 노트’에서 문장·청크·문단을 눌러 재생한다.

처리 상태는 화면에 표시된다. 실패하면 ‘자막·AI 분석 준비’를 눌러 재시도한다. 이미 수집한 자막과 검증한 AI 결과는 재사용한다. 다른 영상을 선택해도 이전 결과와 청취 기록은 보존한다. 백업에는 원본 자막과 AI 분석도 포함된다.

## AI 연결

### Gemini 키 입력 (2026-09-20 추가)

1. 앱의 ‘설정과 백업’에서 ‘Gemini 자막 분석 설정’을 연다.
2. Gemini API 키와 사용할 모델 이름을 입력한다.
3. ‘저장하고 Gemini 사용’을 누른다. 재시작 없이 자막 분석에 Gemini를 우선 사용한다.
4. ‘연결 확인’을 누른다. 짧은 요청을 보내므로 API 사용량이 발생할 수 있다.
5. ‘소리 연습실’에서 영상을 선택하고 ‘자막·AI 분석 준비’를 누른다.

키는 Windows 사용자 계정으로 암호화하여 로컬 데이터베이스의 secret 항목에 저장한다. 앱의 학습 백업에서 제외하며 화면으로 다시 반환하지 않는다. 다른 컴퓨터나 Windows 계정에서는 키를 다시 등록한다. 키 삭제 후에는 Gemini 미설정 상태를 유지하며 다른 유료 API로 자동 전환하지 않는다.

키를 비워 두고 저장하면 기존 키를 유지한다. 교체하려면 새 키를 입력한다. 모델 변경 시에도 저장 후 연결 확인을 진행한다. 기본 모델은 공식 구조화 출력 예제의 `gemini-3.8-flash`이며 입력란에서 변경할 수 있다.

처음 등록할 때는 키 입력이 필요하다. 빈 키나 잘못된 입력은 저장 버튼 아래에서 즉시 안내한다. 저장 결과와 서버 응답 지연도 같은 위치에 표시한다. 키 저장은 API 키 발급이나 실제 연결 성공을 뜻하지 않는다.

키를 붙여넣을 때 앞뒤 공백, 바깥 따옴표, `GEMINI_API_KEY=` 또는 `GOOGLE_API_KEY=` 표기는 자동 정리한다. 키 내부 공백·줄바꿈과 보이지 않는 문자는 구체적인 오류로 안내한다. 키 문자열의 기호만으로 인증 실패를 단정하지 않는다. 저장에는 외부 API를 호출하지 않는다.

Gemini 요청은 [Google 공식 구조화 출력 문서](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en)를 기준으로 구현했다. 키 등록 전에는 대체 응답을 이용한 연결 코드 검증만 가능하며, 실제 계정 권한·할당량·분석 품질은 연결 후 검증해야 한다.

2026-09-20 실서비스 검사에서 `responseFormat.text.mimeType` 요청이 HTTP 400으로 거부되는 것을 확인했다. [REST API 명세](https://ai.google.dev/api/generate-content)의 `responseMimeType` 및 `responseJsonSchema`로 변경하여 짧은 실제 자막 분석이 성공했다. 연결 확인도 자막 분석과 같은 JSON 요청 및 경계 검사를 수행하도록 변경했다.

같은 날 Gemini 실서비스에서 짧은 영상은 4.8초에 39단어·4문장으로 준비됐다. 현재 영상은 문단 인덱스 검증 실패를 발견하여, 각 문장의 문단 끝 여부를 반환하도록 개선했다. 개선 후 50.5초에 3,218단어·456문장/발화·955청크·20문단으로 전체 준비 및 범위 검증이 완료됐다. 이 시간은 해당 요청의 측정값이며 다른 영상이나 재요청의 완료 시간을 보장하지 않는다. 실제 음성 싱크와 의미 구분 품질은 아직 별도 검증이 필요하다.

### 기존 환경 변수 연결

서버 실행 환경에 `OPENAI_API_KEY`가 있으면 OpenAI API를 사용한다. 기본 모델은 `gpt-4.1-mini`이며 `LISTENING_OPENAI_MODEL`로 변경할 수 있다. API 이용료는 ChatGPT 구독과 별개다. 분석 요청에는 공개 영상의 자막을 전송하며, 청취 노트는 포함하지 않는다. 키는 백업이나 브라우저로 보내지 않는다.

로컬 Ollama를 사용하려면 실행 중인 모델 이름을 `LISTENING_AI_MODEL`에 지정한다. 이 설정이 있으면 로컬 모델을 우선한다. 환경 설정을 바꾼 뒤에는 앱 서버를 재시작한다. 키를 문서나 소스 코드에 적지 않는다.

앱 안의 기존 발음 피드백 버튼은 로컬 Ollama 설정을 사용한다. 자막 준비용 OpenAI 연결과 구분한다.

## 시간과 실패 처리

AI는 시간을 만들어내지 않는다. 원본 자막 구간을 보존하고 그 안에서 단어 시간을 추정한다. 의미 구분이 맞아도 실제 소리가 잘릴 수 있어 시작·끝 조정 기능을 유지한다. 아직 음성 기반 단어 정렬을 구현하지 않았다.

영어 자막이 없거나 YouTube가 수집을 차단하면 준비 실패로 표시한다. 영상 설명으로 자막을 지어내지 않는다. 자막 없는 영상의 음성 인식은 아직 지원하지 않는다.

전체 분석은 최대 12,000단어까지 요청한다. 이를 넘기거나 AI가 마지막 단어까지 처리하지 않으면 완료 처리하지 않는다. AI 응답 경계가 잘못되면 한 번 재요청하고, 여전히 잘못되면 실패를 표시한다.

## 2026-09-19 검증

- 기존 영상 `UVnck7nWaB4`: 라이브러리로 448개 자막 구간 수집, 3,218단어 전체 시간 범위 처리 성공.
- 다른 영상 `jNQXAC9IVRw`: 라이브러리로 6개 자막 구간 수집, 39단어 전체 시간 범위 처리 성공.
- 실제 OpenAI 분석 요청: HTTP 429, `credit_balance_exhausted` / `insufficient_quota`로 실패. 실제 AI 출력 품질은 검증하지 못했다.
- 자동 테스트: 여러 영상의 분리, 전체 단어 보존, 시간 범위, 잘못된 경계 거부, 캐시 재사용, 실패 상태, 백업 복원 검사.
- Python 테스트 27개와 프런트엔드 테스트 5개 통과. TypeScript 검사와 앱 빌드 통과.
- 브라우저에서 다른 링크 추가 후 잔액 부족 안내와 문단 분석 미완료 안내를 확인했다. 검증용 ‘Me at the zoo’ 영상이 내 영상 목록에 남아 있다.

자동 테스트의 모델 응답은 검증용 대체 응답이다. 실제 영상의 문장·청크·문단 품질과 청취 싱크가 검증됐다는 뜻은 아니다.
