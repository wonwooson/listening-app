# 화면 조작 회귀 검증

화면 구조, 탭, 포커스를 수정할 때마다 새 빌드에서 수행한다. 기존 데이터베이스에 검증용 기록을 저장하지 않는다. 입력 검증은 기존 값을 보관하고 복원하며 저장 버튼은 누르지 않는다.

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 1 | 영상 설정을 접고 학습 화면 진입 | 영상·재생 버튼·자막 탭이 화면 안에 보이고 페이지 스크롤이 필요하지 않음 |
| 2 | 자막 탭을 클릭하고 즉시 ↑↓ | 목록을 다시 클릭하지 않아도 이전·다음 항목으로 점선 이동, 영상은 이동하지 않음 |
| 3 | ←→ | 단어·청크·문장·문단 전환, 소리 노트 탭으로 이동하지 않음 |
| 4 | 정지 상태 Enter | 선택 항목 시작부터 재생 후 끝에서 정지 |
| 5 | Shift+Enter 후 Enter | 연속 재생 시작, Enter 시 현재 발화 항목의 끝에서 정지하며 되감지 않음 |
| 6 | 소리 노트 → 자막 탭 클릭 → 네 방향키·Enter | 이전 탐색 위치 복원, 단축키 즉시 작동 |
| 7 | 청크·문장·문단 버튼 클릭 후 방향키 | 선택 모드에서 키보드 탐색 가능 |
| 8 | 검색창·노트 입력창에서 방향키·Enter | 문자 이동·줄바꿈 유지, 영상·보기 변경 없음 |
| 9 | 영상 자체에서 앞뒤 탐색과 재생 | 자막 위치 추종과 이어 듣기 유지 |
| 10 | 반복 및 배속 변경, 노트의 이 구간 듣기 | 해당 기능 유지, 재생/멈추기 버튼 크기 변화 없음 |
| 11 | 노트 입력 → 탭 왕복 | 입력 유지; 테스트 입력을 기존 값으로 복원 |
| 12 | PC 1366×768 및 좁은 화면 | PC에서 상단 설정 접힘과 패널 내부 스크롤 확인; 좁은 화면에서는 세로 배치와 문서 스크롤 허용 |

빌드: `npm run build`. 로직 회귀: `npm test`.
실제 영상 탐색은 추정 자막 시간에 기반한다. 브라우저 검증이 음성 경계 정확도를 보증하지는 않는다.

## 2026-09-20 검증 기록

- 새 빌드 성공. 기존 로직 테스트 12개 통과.
- 실제 Chrome에서 자막 탭 클릭 직후와 노트 왕복 후 네 방향키를 확인했다. 문장/청크 버튼으로 보기를 바꾼 뒤에도 목록에 포커스가 돌아왔다.
- Enter로 첫 문장을 재생한 뒤 약 0.7초에서 정지했다. Shift+Enter로 연속 재생한 뒤 약 13.7초에 Enter를 눌렀고 되감기 없이 해당 문장 끝인 약 14.0초에서 정지했다.
- 검색창의 방향키·Enter가 보기와 재생을 바꾸지 않았다. 노트의 방향키·Enter는 문자 이동과 줄바꿈으로 동작했다. 탭 왕복 후 임시 입력이 유지되었고 기존 빈 값으로 복원했다. 저장 버튼은 누르지 않았다.
- 노트의 ‘이 구간 듣기’, 0.75배속, 반복 재생을 확인했다. 반복을 해제하고 1배속으로 복원했다.
- 영상 자체의 10초 앞으로 탐색 후 자막 추종과 이어 듣기를 확인했다.
- 1366×768에서 문서 높이는 768px이고 영상·재생 버튼·자막 패널이 화면 안에 있었다. 노트 탭에서도 문서 높이를 유지했다. 800×740에서는 기존 세로 배치와 문서 스크롤을 확인했다. 검증 후 브라우저 크기를 복원했다.
- ‘영상 설정’으로 소개·영상 선택 영역을 다시 열고 ‘학습 화면으로’로 접을 수 있었다.

남은 검증: 영상 뒤로 탐색은 YouTube 컨트롤이 숨겨져 자동 클릭을 완료하지 못했다. 첫 방문의 저장소 초기 상태, 다른 브라우저, 확대 배율, 전체 화면 영상, 네트워크 지연 중 조작은 이번에 재검증하지 않았다. 이 기록은 모든 영상의 음성 싱크 정확도를 보증하지 않는다.

## 2026-09-20 재생 모드 표시 변경 검증

반복·배속 옆에 재생 모드를 표시했다. 상태는 버튼이 아니라 현재 듣기 방식이다.

- 빌드 성공, 기존 테스트 12개 통과.
- 실제 Chrome에서 자막 탭 클릭 직후와 소리 노트 왕복 후 네 방향키 및 Enter·Shift+Enter를 확인했다.
- 한 번 듣기 후 정지, 연속 재생 중 Enter로 현재 항목 끝 정지를 확인했다. 상태 표시는 각각 ‘구간 한 번 듣기’, ‘계속 이어 듣기’로 전환되었다.
- 반복 체크 시 ‘구간 반복’으로 전환되었다. 1366×768에서 반복·배속·상태·재생 버튼이 한 줄에 보였다. 상태 변화 전후 각 요소의 가로 위치와 폭이 동일했다.
- 배속 변경 및 복원, 노트의 ‘이 구간 듣기’를 확인했다. 사용자 노트에 검증용 기록을 저장하지 않았다. 브라우저 크기를 복원했다.
- 이번 표시 변경에서는 영상 자체의 탐색, 신규 노트 입력 유지, 첫 방문, 좁은 화면을 재검증하지 않았다. 앞선 검증 기록과 구분한다.

## 2026-09-20 재생 모드 버튼 토글 검증

상태 표시를 버튼으로 바꾸었다. 클릭하면 현재 위치에서 연속 듣기와 현재 보기 항목 끝 정지를 전환한다. 정지 중이면 현재 위치부터 재생하고, 반복 설정과 예약을 해제한다.

- 빌드 성공, 기존 로직 테스트 12개 통과.
- 실제 Chrome에서 정지 중 양방향 클릭 전환과 재생 중 전환을 확인했다. 약 7.2초에서 구간 듣기로 전환한 뒤 되감기 없이 약 8.4초에서 정지했다(해당 자막 끝 약 8.3초).
- 자막 탭 클릭 직후와 노트 왕복 후 네 방향키·Enter·Shift+Enter 조작을 확인했다.
- 반복 중 버튼 클릭 시 반복 체크 해제와 계속 이어 듣기 전환을 확인했다.
- 사용자 노트 입력·저장은 수행하지 않았다. 이번에는 모바일 배치·네트워크 지연·영상 끝 경계·빠른 연타는 검증하지 않았다. 자막 시간과 정지 감지는 추정 및 폴링 기반이다.

## 긴 문단 내부 문장 스크롤 회귀

추가 필수 조작: 화면보다 긴 문단의 하단까지 스크롤하고 내부 문장을 클릭한다. 클릭한 문장이 계속 보이고 문단 시작으로 돌아가지 않아야 한다. 이어 듣기에서는 내부 문장이 화면 밖으로 나갈 때만 스크롤한다. 문장 보기로 전환했다가 문단으로 돌아오는 조작과 ‘현재 위치로 돌아가기’도 같은 문장 기준으로 확인한다.

2026-09-20 결과: 빌드 성공, 기존 테스트 12개 통과. Chrome에서 캡처의 ‘there was still lots of stuff carrying on…’ 문장을 클릭했다. 클릭 전 목록 스크롤 5900px, 재생 후 5927px이며 문장은 화면 y=662px에서 y=635px로 이동하여 계속 보였다. 문단 시작으로 돌아가지 않았다. 자막 탭 및 노트 왕복 후 네 방향키와 Enter·Shift+Enter를 확인했다. 사용자 노트 입력·저장 버튼은 사용하지 않았다. 다른 영상, 모바일, 매우 긴 단일 문장과 네트워크 지연은 미검증이다.

## 학습 기록의 소리 노트 모아보기

학습 기록에서 작성한 노트만 보기/전체 보기, 영어·한글 검색, 영상 필터, 피드백 펼치기, 이 구간과 노트 열기를 확인한다. 열었을 때 저장한 영상·시간·세 기록 필드가 복원되고 자동 재생하지 않아야 한다. 연결할 자막이 없는 기록도 삭제하거나 숨기지 않는다.

2026-09-20 검증: 빌드 성공, Node 테스트 12개와 API 테스트 8개 통과. API 테스트는 같은 현재 자막으로 대응되는 두 과거 노트 및 연결이 없는 노트가 모두 남고 최신순으로 정렬되는지 검증했다. 실제 Chrome에서 영어 구절 검색 후 2:55.7–2:57.5 기록을 열고 소리 노트 탭·처음 들린 소리·피드백·다시 들은 소리 복원을 확인했다. 자막 탭 및 노트 왕복 후 네 방향키·Enter·Shift+Enter를 검증했다. 사용자 노트에 시험용 입력을 저장하지 않았다. 실제 다른 영상 간 이동과 모바일 배치는 미검증이다.

추가 확인: 전체 보기에서 70개 항목이 표시되었다. 작성한 노트 필터, 영상 선택, 한글 ‘아리’ 검색, 발음 피드백 펼치기도 정상 동작했다.

## 학습 기록 탭과 기간 접기

1. 학습 기록의 세 탭에서 선택한 내용만 보이는지 확인한다. 탭의 좌우 방향키·Home·End와 선택 표시를 확인한다.
2. 월 → 주 → 일 순서로 접거나 펼친다. 이번 달·이번 주·오늘은 기본으로 펼치고 지난 기간은 접혀 있어야 한다. 주는 월요일 시작이며 월 경계에서 해당 월의 날짜만 포함한다.
3. 모두 접기·모두 펼치기 및 탭 왕복 후 펼침 상태 유지를 확인한다.
4. 과거 기간의 소리 노트를 검색한다. 일치하는 기록은 접힌 기간 안에서도 펼쳐 보여야 한다. 해당 노트 열기와 저장 내용 복원을 확인한다.
5. 최근 연습 노트에도 같은 월·주·일 조작을 적용한다. 의미 이해 요약은 전체 기간 누적임을 표시한다.
6. 별도 임시 자료로 현재·지난주·지난달·지난해를 검증한다. `python tests/serve_history_fixture.py`는 임시 DB와 개발용 포트 5173을 사용하며 사용자 DB를 읽거나 수정하지 않는다. 해당 포트가 사용 중이면 기존 서비스를 종료하지 말고 먼저 확인한다.

2026-09-20 결과: 빌드 성공. 날짜 그룹 테스트 5개 포함 Node 17개, API 9개 통과. 월말·연말의 주, 윤년, 날짜 없는 기록, 100건 초과 기록 보존을 검증했다. 실제 Chrome의 임시 자료에서 각 기간 접기/펼치기, 전체 접기/펼치기, 탭별 내용 분리와 펼침 상태 유지, 과거 노트 검색과 노트 복원을 확인했다. 390×844 화면에서 세 탭이 화면 폭 안에 있고 문서 가로 넘침이 없었다. 자막 탭과 소리 노트 왕복 후 네 방향키·Enter·Shift+Enter도 확인했다. 이번 작업에서는 영상 원본 탐색·반복·배속·소리노트 편집 저장·다른 브라우저는 재검증하지 않았다.


## 모바일 터치 청취 변경 검증

갤럭시 S22에서 새로고침 후 다음을 확인한다.

1. 기본 화면에 영상·자막·설정이 보이고 부가 버튼은 숨겨지는지 확인한다. 설정에서 배속·검색·소리 노트로 접근하고 다시 접는다.
2. 틀 여백 또는 시간 표시를 두 번 눌러 이어 듣기 → 즉시 정지를 확인한다.
3. 청크·문장을 눌러 선택 끝에서 0.7초 쉬고 반복하는지, 같은 항목을 다시 눌러 정지하는지 확인한다. 쉬는 동안에도 다시 눌러 반복 예약이 취소되어야 한다.
4. 단어 시작·끝 선택과 선택 범위 단어 재선택 정지를 확인한다.
5. 좌우 스와이프로 네 보기를 왕복한다. 세로 스크롤은 모드를 바꾸지 않고 스와이프는 재생을 시작하지 않아야 한다.
6. 영상 자체 탐색 후 자막 추종, 긴 문단 아래 문장 선택 후 위치 유지, 가로 회전, 노트 왕복 후 기록 유지를 확인한다.

PC 임시 DB 브라우저 검증: 자막 탭 클릭 직후 네 방향키와 Enter 한 번 듣기 정지(약 0.6초)를 확인했다. Shift+Enter 연속 재생 중 Enter를 누른 뒤 현재 항목 끝(약 12.2초)에 정지했다. 소리 노트 왕복 후 네 방향키와 Enter가 동작했다. 1366×768 문서 높이는 768px였다. 사용자 DB에 테스트 기록을 저장하지 않았다.

미검증: 갤럭시 S22의 새 터치 동작 전체, 반복 중 재선택·대기 취소, 가로 회전, 이번 변경 후 영상 원본 탐색·배속 변경. 기존 모바일 재생 성공과 구분한다.

추가 검증: 빌드 성공, 스와이프 판정 2개를 포함한 자동 테스트 19개 통과. 임시 DB 브라우저에서 노트 입력·줄바꿈 및 탭 왕복 후 내용 유지, 검색 입력의 방향키·Enter 분리를 확인했다. 실제 사용자 기록은 수정하지 않았다.


## 모바일 영상 폭·상태 버튼 변경

영상 오른쪽 여백 원인인 세로 flex의 시작 정렬을 stretch로 변경하고 영상·iframe을 패널 폭에 맞췄다. 멈춤/반복/이어 듣기는 실제 플레이어 상태로 표시한다. 반복은 선택 범위 처음부터, 이어 듣기는 현재 위치부터, 멈춤은 대기 예약까지 취소한다.

빌드 성공, 자동 테스트 19개 통과. 임시 DB 브라우저에서 자막 탭 및 노트 왕복 후 네 방향키·Enter·Shift+Enter를 확인했다. 첫 구간 Enter 정지는 약 0.6초, 연속 재생 중 Enter 정지는 약 12.2초였다. 사용자 DB에 검증 기록을 저장하지 않았다.

실기기 확인 필요: S22 영상과 자막의 좌우 폭 일치, 세 상태 버튼 터치와 강조 표시, 반복 대기 중 멈춤, 이어 듣기 전환 시 되감기 없음. PC의 원본 영상 탐색·배속·노트 편집과 모바일 가로 회전은 이번 변경에서 재검증하지 않았다.


## 상태 버튼 세로 크기 축소 및 사용자 실기기 확인

사용자는 갤럭시 S22에서 설정 표시, 틀의 연속 재생·정지, 내부 청크·문장 반복·정지, 단어 범위 선택·정지, 좌우 스와이프, 영상 폭, 세 상태 버튼의 정지·반복·현재 위치 이어 듣기를 정상으로 확인했다. 이는 사용자 실기기 보고이며 자동 검증 결과와 구분한다.
